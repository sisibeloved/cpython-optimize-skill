# 代码优化基础

来源：Cooper & Torczon《Engineering a Compiler》2nd ed，
§8.3 Scope of Optimization（PDF p442）、§8.4–8.7 各作用域优化（p445–494）、
Ch9 Data-Flow Analysis（p500）、Ch10 Scalar Optimizations（p564）。
页码为 PDF 页，印刷页 ≈ PDF−25。

## 作用域分类（决定分析精度与成本，§8.3 原书的四层划分）

| 层级 | 范围 | 典型优化 |
|---|---|---|
| 局部 local | 单个 basic block | 局部值编号、窥孔、代数化简 |
| 区域 regional | 块以上、过程以下（如整个循环） | 循环不变量外提、区域冗余消除 |
| 全局 global | 整个过程（CFG） | 常量传播、CSE/GVN、DCE、拷贝传播 |
| 全程序 whole program | 跨过程（IPO） | 内联、过程间常量、逃逸分析 |

注：基本块的两个性质（顺序执行、全有或全无）使局部方法能证得更大作用域证不了的
更强事实（§8.3，p417 印刷页）——这是"局部优化有时不可被全局替代"的理论根据。

分析基本都建立在 CFG + 数据流方程（前向/后向，must/may）之上；
迭代至不动点，支配树是"必经路径"结构的核心工具。

## 常见优化的前置条件（评审"优化是否安全"的清单）

- 常量传播：SSA + meet 操作语义正确（尤其浮点 NaN、有符号溢出不可假设）。
- 死代码消除：副作用判定准确（内存写、调用、volatile 不可删）。
- CSE/GVN：表达式等价判定（别名分析不足时保守）。
- 强度削减：循环归纳变量（IV）识别正确。
- 内联：被内联方语义（异常、副作用）与调用点假设一致；JIT 还要考虑
  内联后的代码膨胀对 IC 命中、编译时间的影响。
- 循环不变量外提（LICM）：**安全性**（外提不引入新异常/新内存访问）与
  **收益**（循环确实会执行）都要成立；空循环/提前 break 场景是经典坑。
  书中该主题的完整形式是 **lazy code motion（LCM）**（§10.3.1，p576）：用
  available expressions 推广的数据流方程同时决定"哪些式子动、动到哪"，并覆盖
  部分路径冗余；hoisting（§10.3）是它的代码体积导向变体。
- 公共子表达式跨基本块移动：受支配关系约束。

## 优化 pass 顺序的通用规律

- 清理性优化（常量折叠、代数化简）先行，为后续提供更简单的 IR。
- 数据流类 pass 相互催化（常量传播 ↔ 死代码消除循环到不动点）。
- 降低层级的 pass（SSA 消解、栈槽物化）放在机器无关优化之后、调度分配之前。
- JIT 特有：**编译预算决定 pass 管线深度**；tier 升级时才跑更贵的管线。
  CinderX 的 tiering 行为以代码为准，这里只提供"为什么分层"的框架。

## JIT 相对 AOT 的差异点（CinderX 语境常踩）

1. **投机优化**：基于类型反馈（inline cache）假设；假设失效必须 deopt 回退——
   优化的正确性契约包含"守卫条件完整性"，评审时守卫缺失=正确性 bug。
2. **on-stack replacement（OSR）**：长循环中从解释器切到优化代码，栈帧状态
   迁移是正确性敏感点。
3. **去优化点的状态完整性**：任何时刻的优化代码状态要能映射回解释器可见状态。

## 落地查证

- 优化方案落到指令选型（如用条件选择替代分支）→ 先读 isa-instruction-lookup 的
  `optimization-intent-map.md`，再 `find_instruction_by_function` 检索候选。
- 断言某优化依赖的指令在某平台可用 → `filter_by_environment`。
- 前置条件清单的判定涉及具体指令语义时 → `lookup_instruction` 比对伪代码，不凭记忆。
